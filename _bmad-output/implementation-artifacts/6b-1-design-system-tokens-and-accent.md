# Story 6b.1: The design system — tokens, typography, and the accent that stays reserved

Status: ready-for-dev

Epic: 6b — *L'interface de la maquette* (inserted 2026-08-13 by correct-course,
`sprint-change-proposal-2026-08-13.md`). **First story of the epic**, so `epic-6b` moves to
`in-progress` with it.

## Story

As the operator,
I want the product to look like the reference mock,
so that what I was shown is what I run.

## What this story does NOT do

It ships **no screen**. `templates/` gains no file, the router gains no route, and the ten
navigation entries are story 6b.2's business. This story changes what the ONE existing page is made
of — its tokens, its typefaces, its theme — and builds the machinery the next eleven stories rebuild
their screens with.

It also does **not** write the example dataset, the marker, or any copy: 6b.3 and 6b.10 own those.

### 1b. What D55 actually requires, and the trap it names

`architecture.md:3168-3230`, in full force here:

- **`build.rs` invoking the Tailwind CLI is REFUSED.** Not a preference: a `cargo build` that
  rewrites a git-tracked file is a fault, `cargo install --path .` must work on a machine with no
  Tailwind binary, and two generators for one byte is *"the worst of both"*. `cargo xtask css`
  instead — **`xtask` is nobody's dependency (D56), `build.rs` would be everybody's.**
- **`@source` is relative to the CSS FILE, not to the manifest** — `../templates/`, never
  `./templates/`.
- 🔴 **A wrong `@source` path breaks NOTHING VISIBLY**: Tailwind finds nothing, the build is green,
  `app.css` silently loses half its classes, *"and you discover the colourless status pill in
  production."* This is the same shape as constraint 5 of the epic, and it is why the gate below
  counts classes **in the generated CSS** rather than reading the config.
- ⚠️ **`architecture.md:619` (finding F16) records that the UX spec's Tailwind note describes an API
  that no longer exists**: v4 removed the JS-config `content` and `safelist`. Use `@source` and
  `@source inline()`. *The decision stands; the syntax does not.* Do not implement the spec's letter.

## 2. The mock's tokens — extracted, not paraphrased

Source: `~/travail/Projets actuels/opencmdb/documents/opencmdb - maquette.html` (496 068 bytes,
2026-08-13), **outside this repository**. Its CSS lives inside a JSON-escaped string; unescaped, it
carries exactly **one `:root` block**:

```
--color-bg: #f2f2f3      --color-surface: #e9e9ea    --color-text: #1d1f20
--color-accent: #5980a6  --color-accent-2: #728fab
--color-divider: color-mix(in srgb, #1d1f20 16%, transparent)

neutral-100..900   #f5f5f8 #e7e7ea #d4d4d7 #b7b7ba #98989b #7a7a7d #5d5d60 #424244 #2b2b2d
accent-100..900    #eef6ff #d6ebff #b5d9fd #94bce3 #749dc4 #597ea3 #416180 #2c455d #1d2d3d
accent-2-100..900  #eef6ff #d6ebff #bdd8f2 #9ebbd8 #7e9cb8 #627d98 #486077 #314457 #1f2d3a

--font-heading: "Barlow Condensed", system-ui, sans-serif   --font-heading-weight: 600
--font-body: "Barlow", system-ui, sans-serif

--space-1,2,3,4,6,8: 3.4 6.8 10.2 13.6 20.4 27.2 px   (SIX tokens — no --space-5, no --space-7)
--radius-sm/md/lg: 2px 4px 7px
--shadow-sm/md/lg: ink-tinted, via color-mix
```

Four observations that are decisions, not transcription:

1. 🔴 **The mock has NO amber token.** Its `--color-accent` is the blue. So `--accent-document` is an
   ADDITION this product makes to the mock's system, not a token lifted from it — which is exactly
   what the epic's constraint 3 and AC2 describe, and it means nothing in the mock can be consulted
   to check it.
2. ⚠️ **The mock DOES carry a monospace token — the first draft said it did not, and was refuted.**
   Four tokens live **outside** `:root`, inline on the root `<div>`: `--mono` (a **system stack**:
   `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`), plus `--muted`, `--line` and `--rp`.
   🔑 So the mock and `app.css:37-40` already agree: a system monospace, nothing embedded. The
   conclusion survives — **no monospace face is embedded, the AC names two families and only two** —
   but there is **NO divergence to register**, and the draft would have had dev write a register row
   for one. *A token block extracted from `:root` alone is not the mock's token set.*
3. ⚠️ **The mock's radii are 2/4/7px and the UX spec says `3px` everywhere** (`--radius: 3px` at
   `:678`, *"Radius `3px` everywhere"* at `:839`). Guy's decision (3) of 2026-08-13 adopts the mock's
   palette and typography; **radius is neither**. Left as the mock's three-step scale, registered.
4. ⚠️ **`color-mix()` and the shadows.** The mock derives its dividers and elevation through
   `color-mix(in srgb, …)`, while the UX spec bans shadows outright — *"elevation via hairline
   borders, no shadows"* (`:839`; the same ban in other words at `:679`). Adopting the mock's `--shadow-*` tokens would contradict a
   specified rule; **the tokens are carried into the sheet, and nothing in this story USES them** —
   the same treatment the dark set gets in AC3, and for the same reason.

## 3. 🔴 The fonts are NOT in the mock, and the AC assumes they are somewhere

Measured, because *"lift the tokens and the fonts from the mock"* is the obvious plan and it fails:

- the mock declares **15 `@font-face` rules**, resolving to **five faces**: Barlow 400 / 500 / 700
  and Barlow Condensed 400 / 600;
- every one has `src: url("<uuid>")` — an artifact-host reference. **The bytes are not in the file**:
  `base64` occurs exactly **once** in 496 KB, inside the viewer's own JavaScript, and there is **no**
  `fonts.googleapis` / `fonts.gstatic` reference at all.

**Provenance, verified upstream rather than assumed** (`github.com/jpt/barlow`, the designer's own
repository, which carries `OFL.txt`, 4 377 bytes — SIL Open Font License 1.1):

| File | Bytes |
|---|---|
| `Barlow-Regular.woff2` | 58 964 |
| `Barlow-Medium.woff2` | 59 180 |
| `Barlow-Bold.woff2` | 60 492 |
| `BarlowCondensed-Regular.woff2` | 58 652 |
| `BarlowCondensed-SemiBold.woff2` | 60 508 |
| **total** | **297 796 (~291 KB)** |

🔑 **`rust-embed` needs no wiring for this.** `page.rs:24-26` embeds `#[folder = "assets/"]`, so
files dropped in `assets/fonts/` are embedded by the mechanism that already exists — and they are
served under `/assets/*`, which story 6.1 left as one of the only two PUBLIC prefixes. **The binary
grows by ~291 KB and that is the whole cost**; state it in the story record rather than letting a
release note discover it.

⚠️ **The licence must be RECORDED, which the AC says and which is not the same as respecting it.**
OFL 1.1 requires the copyright notice and licence to travel with the fonts. `OFL.txt` lands beside
them (it is not served — it is not a `.woff2`, and no template links it), and `README.md`'s
attribution is 6b.12's business, registered.

⚠️ **A `sha256` lock is NOT prescribed here.** The `fixtures` gate locks the corpus because a fixture
is an ORACLE and a silent edit falsifies a measurement; a font file is neither. Named so that the
next reader knows it was considered and refused, not forgotten.

## 4. The accent: the one deliberate divergence, and the gate it must not retire

`app.css:12` carries `--accent: #d99a4e` with the doctrine in its own comment — *"amber — reserved
for the document action, never decorative"*. The mock makes its **blue** the general primary (nav
selection, primary buttons, occupied IPAM cells).

🔑 **These are two doctrines, not two palettes** — *"this colour means the GESTURE"* against *"this
colour means the PRODUCT"* — and the UX spec says in so many words that a palette swap keeping the
second **silently retires a specified gate** (`:590-592`).

So: the mock's blue becomes structure, and the amber survives the swap **renamed**
`--accent-document`, which is what the UX spec already calls it at `:682`.

🔴 **The rename touches SIX sites, not two, and the story's first draft named two that do not
exist** (it said `:70, :76` — a closing brace and a `padding` rule). Measured:

| `app.css` | What it is | Where it must land |
|---|---|---|
| `:12` | `--accent: #d99a4e` — the **dark** definition | renamed `--accent-document` |
| `:22` | `--accent: #b5793a` — the **light** definition, and the one that RENDERS after AC3 | renamed |
| `:62` | `.card:focus` outline | **structure → blue** |
| `:77` | `.refresh` text colour | **structure → blue** |
| `:78` | `.refresh` border | **structure → blue** |
| `:83` | `.refresh:hover` fill (`color-mix`) | **structure → blue** |

⚠️ Move only the border and the outline — the two the draft named — and the refresh button keeps
amber text and an amber hover, so AC4's *"zero non-gesture uses"* reds against the story that asked
for it. **The light definition at `:22` is the one that matters most**: after AC3 it is the set that
renders, and it is absent from every earlier draft of this section.

⚠️ **The register row is (e), not (a)** — row (a) is story 6.1's two-browser Basic measurement,
**fully discharged 2026-08-14 with no residual**, and editing it would corrupt a closed record. Row
(e) is *"The `--accent` colour conflict"*, and its substance is **not** a token name: story 5.14b's
guard asserts the identity section never reaches `--accent`, and 6.4's Document button there will be
legitimately amber. 🔑 **Row (e) already anticipates this ordering** — *"Epic 6b's story 6b.1
re-tokenises `app.css` first, so whoever lands second re-checks the guard exists. Owner: story 6.4,
conditional on 6b.1's ordering."* So this story does **not** take the row over; it lands first and
must leave the guard **findable**, which is a weaker and truer obligation than the draft's
*"re-owned here"*.

`gap.html:2` is `<html lang="en" data-theme="dark">`, and `app.css:5-25` carries **both** sets with
nothing to switch them. So AC3 is not the postponement of an unbuilt feature — **every existing

dark tokens **stay in the sheet, unreferenced**, so their return is a story rather than an
excavation. What it does not do: write the release note. That is 6b.12, and it is already registered

## 6. The guard: a green diff is not evidence that a pill has a colour

Epic constraint 5 and D55 name the same failure, and it is the one this project has met before under
another name (*a guard placed where the defect cannot occur reads as coverage and is none*, Epic 5's
retrospective).

**The gate must count classes in the GENERATED CSS**, per `architecture.md:3201-3204`: regenerate
into a temporary file, compare against the committed `app.css`, and assert each class built in Rust
is present. 🔑 **`@source inline()` alone is NOT a gate — it is a list someone forgets to update.**

⚠️ **The class list must be derived from the tree, not typed into the gate**: a gate carrying its own
copy of the class list is green on the day a Rust file gains a class nobody added to the gate. Where
the derivation cannot be total, the gate must **fail on an unclassified construction site** rather
than pass — story 6b.3's *"a route added without a declared nature must fail rather than default"*,
one story early.

## 6b. 🔴 AC6 and AC7 COLLIDE, and the collision is most of the real work

`app.css` is **not a token sheet**. It is 150 lines of hand-authored component CSS — **16 bespoke
class families** across 36 rules: `.topbar .brand .tagline .wrap .card .entity .refresh .mono .muted
.cols .rows .clear .gaps .count .abstentions .identity` — plus a `prefers-reduced-motion` query.
**Tailwind generates none of them.**

So AC6 (*the committed sheet IS the generator's output*) and AC7 (*the existing page renders
unchanged, templates untouched*) cannot both hold unless those rules are carried across
deliberately. The story must say WHERE they go, and the honest options are three:

| | Where the component rules live | Cost |
|---|---|---|
| **(i)** | `@layer components` inside `tailwind.css`, emitted into `app.css` | AC6 and AC7 both hold; `tailwind.css` becomes the real source file |
| **(ii)** | a second committed sheet, `app.css` generated + `components.css` hand-authored | two `<link>`s, and AC6 narrows to the generated half |
| **(iii)** | rewrite both templates in Tailwind utilities | **contradicts this story's own *"ships no screen"*** and does 6b.2/6b.4's work early |

🔴 **(iii) is what a dev agent does by default if the story stays silent**, because it is what
"adopt Tailwind" usually means. **Say which one.** The draft's *"`templates/` gains no file"* is not
the same promise as *"no template changes"*, and only the first is kept under (i) or (ii).

⚠️ **And a committed test READS this file**, which is the carrier nobody predicted:
`page.rs:1163`, `the_identity_sections_own_rules_never_reach_for_the_accent`, does
`include_str!("../assets/app.css")`, scans from each `.identity` selector to its closing brace, and
asserts **`block.len() >= 4`** as an explicit *premise* — its own message says *"if the selector is
renamed this count is what tells you, rather than a silently empty scan"*. A generated sheet without
`.identity` reds it **on the premise, before reaching the assertion the test exists for**. 🔑 That is
this project's assertion-order family for the fifth time, and here it is a FEATURE: the guard was
built to notice exactly this.

🔑 **It is also a `--accent` consumer §4 does not list** — the literal string, in Rust. Substring
matching means `--accent-document`.contains(`--accent`) stays `true`, so the rename does **not**
silently green it; but T4 touches it and AC4 must not pretend otherwise.

## Acceptance Criteria

Derived from `epics.md:2110-2130`, each one made measurable. **AC numbering is this story's own.**
The epic's four bullets map to **AC2 · AC4 · AC3 · AC5** — tokens+fonts, the reserved accent, the
light/dark swap, the Rust-built classes. ⚠️ **AC1, AC6, AC7, AC7b and AC8 are this story's OWN
additions and derive from no epic bullet** — AC1 because §1 measured the chain absent, AC6/AC7
because a generated sheet replacing a hand-authored one is a regression risk the epic never
considered, AC7b from register row (i). *(The first draft mapped the four bullets to
AC2/AC4/AC6/AC7, which is wrong for half of them.)*

**AC1 — the chain exists and is nobody's dependency.**
`cargo xtask css` regenerates `crates/opencmdb-bin/assets/app.css` from `assets/tailwind.css` using
the **pinned standalone Tailwind binary** (v4.3.3, released 2026-07-16 — `tailwindcss-linux-x64`,
and `-musl` for the distroless/static-musl image of story 3.9). **No `build.rs` is added** (D55), the
binary is not committed (`.gitignore:44-47` already ignores it), and `cargo build` on a machine
without it still succeeds. A test or gate asserts `xtask` is in nobody's dependency graph — D56's
existing rule, which must not regress when `xtask` gains a subcommand.

**AC2 — the palette and the typefaces are the mock's.**
The generated sheet carries the mock's light base and the three ramps of §2, and
**Barlow / Barlow Condensed are embedded** (five `.woff2` under `assets/fonts/`, from `jpt/barlow`,
with `OFL.txt` beside them) and referenced by `@font-face` with **no external request** — asserted
by a test that greps the generated CSS and every template for `http`, `//fonts.`, and `@import url(`.

**AC3 — light renders, dark stays unreferenced.**
`data-theme="dark"` is gone from `gap.html`; the dark token set is still present in the sheet and
**referenced by nothing** — asserted in both directions, because *"still present"* and *"unused"*
are two claims and one of them is the one that rots.

**AC4 — the accent means the gesture and nothing else.**
`--accent-document` (`#d99a4e`) is used by the documenting gesture only. The two current `--accent`
consumers that are structure (refresh border, focus outline — `app.css:70,76`) use the blue.
🔴 A test asserts `--accent-document` appears **exactly** where the gesture is and nowhere else;
today the gesture's own surface does not exist yet (story 6.4), so the honest assertion is
**zero non-gesture uses**, and it must be written so that it still means something when 6.4 adds
the first legitimate one.

**AC5 — the classes built in Rust survive the build.**
The gate of §6 regenerates into a temp file, compares against the committed `app.css`, and asserts
every Rust-built class is present in the OUTPUT. It reds when an `@source` path is wrong.
⚠️ **Prove it by breaking the path**, not by trusting the green.

**AC6 — the committed CSS and the generated CSS are the same bytes.**
`cargo xtask ci` reds if `app.css` is stale. This is what makes AC1's *"committed, not built"* safe.
🔴 **Unsatisfiable together with AC7 until §6b's option is chosen** — the 16 hand-authored component
families are not Tailwind output. Choose (i), (ii) or (iii) before writing a line.

**AC7 — the page still renders and still says the same things.**
The existing gap page's behaviour is unchanged: same routes, same strings, same i18n keys, the
identity-reach pair of story 5.14b intact. **No template gains or loses a sentence.** The one page
this product has must not become collateral damage of its own restyling.

**AC7b — the D37 filename drift is closed, because the register names THIS story as its owner.**
`deferred-work.md` row **(i)**: the vendored asset is `htmx.min.js`, unversioned, where
`architecture.md:3406` prescribes `htmx-<ver>.min.js` — *"COMMITTED, version in the filename. Never a
CDN. (D37)"* — under `assets/vendor/`. **Owner: Epic 6b story 6b.1**, i.e. here. 🔑 This story is
already rewriting what `assets/` contains and what the template links; doing it now costs one rename
and one `<script src>`, and deferring it means touching the same two lines twice. ⚠️ It was absent
from this story's first draft — **the second consecutive story to miss a `deferred-work.md` row that
names it by number**, which is a finding about the reading, not about the row.

**AC8 — the live test count lives HERE**, in this file, and is not copied into `CLAUDE.md`,
`docs/project-context.md` or `sprint-status.yaml` (story 6.1's AC8 rule, F2).
