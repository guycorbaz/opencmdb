**(b) Guards that could not fail — 3 of 3.** 14.5's AC3 own field was carried by NOTHING: deleting

## 4. The apparatus — did A1 and A2 prevent what they were built for?

This is the question this retrospective exists to answer, and it has a measured answer in two halves.

**A2 — `cargo xtask mutate` names the red tests — WORKED, and the stories say how.** On 14.4c's own
first pass both contradicted predictions were diagnosed from the driver's `red:` lines with no replay
by hand. In 14.5, M2's contradiction is what located a hole: the definition route's VLAN refusal,
AC3's first half, had no test at all. Its refusals are results too — M6 was REFUSED because the
mutation left invalid Rust.

⚠️ **What A2 does not reach is exactly where 14.5's and 14.6's instrument defects happened.** DDL is
still undriveable — four stories have now routed around it with purpose-built scripts, and *a debt
four stories route around is a practice*. **14.5's worst instrument defect was a defect of the
hand-written substitute, not of the driver.** The browser gates are still not driven, and that is
where the stale server and the un-exported credentials occurred.

**A1 — `cargo xtask record` — CLOSED THE ARITHMETIC, AND THE DEFECTS MIGRATED OUT OF THE BLOCK.** Not
one number in either block could be falsified; 14.5's review refuted its own suspicions about it.
Then the same classes recurred four ways, in the two stories written immediately after it:

1. 🔴 **The anchor-collision class recurred ON THE TOOL'S OWN CONVENTION, one story later.** 14.4c's
   review found an edit anchored on `## Dev Agent Record` destroying its file with the checker
   exiting 0. In 14.6 an edit anchored on **`## Record`** — the heading 14.4c minted — **cut AC13 in
   half**, burying the entire *Second review round* section between its two halves. Exactly one line
   in the file equals `## Record`, so the checker saw a valid block and answered **✅ — printed
   inside the wreckage it could not see.**
2. 🔴 A second live count elsewhere in the file (14.6's 742 against 744): §3's named limit.
3. 🔴 A prose *registered* claim with no `registered:` line (14.5's AC2 divergence): §3's named limit.
4. 🔴 **An obligation carried by an EDIT is structurally invisible**: 14.6 asserted the DDL-pass
   registration in three places and wrote nothing, because the checker compares the rows a branch
   ADDS.
5. 🔴 **Everything outside the block is unread**: `Status:` was stale in **both** stories written
   after the tool — the very defect the partial retrospective's §8 had just fixed by hand — and 14.6
   shipped no Change Log at all.

🔑 **The honest summary: A1 made the arithmetic right for the first time in this epic, and it did not
reduce the record-defect rate, because the defects moved to the parts of the file it declines to
read — and its own §3 predicted three of the four, in writing, before either story ran.**

🔑 *A checker that validates a block cannot tell you the document around it was destroyed to make
room for the block.* That sentence is this epic's transferable lesson, and it generalises: **every
instrument this project has built measures a named region, and the defect moves to the region next
to it.**

⚠️ One more limit, found while running the tool during this retrospective: **`cargo xtask record`
cannot check a story file after its story is merged**, because `base:` stops being the branch point
by construction. It refuses honestly (exit 2) rather than answering wrongly, which is the contract
working — but it means the tool is unavailable at exactly the moment a retrospective audits a record.

## 5. Which review layer found what — the blind layer's streak ended

The partial retrospective recorded the blind layer finding a HIGH the sighted layers missed in **at
least 5 of 7**. **In these three it is 0 of 3 for the story's own headline finding.** The headline
moved, in all three, to a layer that RUNS something: the auditor for 14.4c, the auditor and the edge
layer together for 14.5, the edge layer for 14.6.

⚠️ **This is not an argument for dropping it.** The blind layer contributed distinct findings in all
three — five blind-only patches in 14.4c, the two detached doc comments in 14.5 (*"it reached the
blind layer and no gate"*), AC12's over-claim in 14.6. What changed is the KIND of defect these
stories carried: 14.5's and 14.6's headlines were both *a guard that cannot fail*, and **a guard that
cannot fail is established by running it, not by reading it.**

⚠️ **And the three stories record their review findings three different ways**: 14.4c has a per-finding
list with its layer; 14.5 has prose with no list; **14.6 has no review section at all**, its record
dispersed into the ACs, the mutation table and the Completion Notes. That is why this retrospective's
layer attribution had to be reconstructed from each story's own headline framing rather than counted.

## 11. Key takeaways

1. **Every instrument this project builds measures a named region, and the defect moves to the region
   next to it.** A1 made the arithmetic right and the record defects moved to `Status:`, the Change
   Log, and the criteria. The tool's own §3 predicted three of the four before either story ran.
2. **A checker that validates a block cannot tell you the document around it was destroyed to make
   room for the block** — and it will print ✅ inside the wreckage.
3. **The blind layer's streak ended, and the reason is instructive rather than alarming**: both
   headline defects were *a guard that cannot fail*, which is established by running, not by reading.
   Keep the layer; do not read its streak as its value.
4. **A scripted edit that detaches a doc comment from its item is a fourth defect class with no
   possible gate**, six occurrences in two stories, and only a reader has ever caught it.
5. **A retrospective that says "closed" is not a closure** unless it writes into the file the next
   story reads.
