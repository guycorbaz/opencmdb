## 🔴 The central finding: a diagnosis written from plausibility, not measurement

Stories 4.15 and 4.17 recorded a real, measured symptom: **8 test failures across 5 runs with
identical sha256 and a clean `git status`, then 15+ consecutive green runs.** That part is sound.

A **cause** was then written next to it: *"the corpus was transiently replaced by a stale server
state; `cloud-drive-daemon` active on the tree."* That cause was never verified. It propagated
into 4.15's review findings, 4.17's Change Log, the epic report, and the draft of this
retrospective — four documents.

Guy challenged it during this retrospective. It is **refuted by measurement**:

| Check | Result |
|---|---|
| `cloud-drive-daemon` process | **none running** |
| Mount type of the tree | **local ext4**, `/dev/nvme0n1p2` — not a network mount |
| Rows in Drive's `history.sqlite` touching `opencmdb` | **0 — none, ever** |
| Last Drive sync activity on `/home/gcorbaz/Synology/devel` | **2026-07-12 13:37** |
| First commit of `opencmdb` | **2026-07-17 19:36** |

Guy had **deliberately stopped** Drive synchronisation on `devel` because it was causing
problems. The repository was created **five days after** he did. The tree has never been synced
while it existed. The directory being named `Synology/` made the wrong answer plausible on every
axis except the one that was checkable.

**Consequences, stated exactly:**

1. **The cause of the 8 failures is UNKNOWN.** We stopped looking because we believed we had
   found it. This is the only red of the entire epic that CI never saw (47/47 green).
2. **The standing house rule — *name the test or the measurement behind every claim* — was being
   applied to code only.** Reviews patched overclaiming doc comments all epic long. Nobody
   applied the same rule to an environment diagnosis.
3. The refutation is recorded here and in a GitHub issue. The merged story files keep their
   period text — history is not rewritten — but no live document carries the false claim.

### Three things Epic 5 must enter with its eyes open

1. **`l2-virtual-mac-prefix` is the corpus's first STRUCTURAL rule id.** If Epic 5 implements that
   ingestion-time reading under a different name, the trap reds as `rule_mismatch` and a

2. **The gate never compares CAUSES, only rules.** An engine that abstains for the wrong reason
   **passes** NFR4's gate. The cause is recorded truth, not gate mechanics. Epic 5 must not read
   the green gate as coverage of causes.
3. **The corpus is a locked SPEC.** Epic 5 will bump it; every bump is deliberate and re-hashed.

## Key takeaways

   with everything except the one verifiable fact. Extend "name the measurement" past code.

   mandatory rather than optional, on Guy's call.

   Applies directly to the Epic 5 breakdown that follows.
4. **An action item that lapses in silence costs more than one that is closed out loud.**
   Epic 3's `xtask verify` went a whole epic unmentioned; it is closed here with its reason.
